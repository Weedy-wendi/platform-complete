# Pingce 可维护性与迭代手册

**版本**: 1.0.0 | **日期**: 2026-11-05 | **关联**: `constitution.md` v1.4.0、`module-map.md`、`subagent-protocol.md`

本文件回答一个问题：**这个系统怎么在 1–3 年里持续改、持续发、持续有人接手，而不变成没人敢动的遗产。**

---

## 1. 判据

> **可维护 = 改得动、看得清、接得住。**
> **可迭代 = 反馈环短、兼容策略清楚、回滚有路。**

三条推论：

1. **可维护性不是阶段，是预算。** 不预留容量还债，债只会越滚越大。
2. **可维护性不是文档，是失败条件。** 写在文档里的规则会被忘记，写进 CI 的规则不会。
3. **评测平台的第一可维护性是「可复现」。** 结果说不清，其他都无从谈起。

---

## 2. 三个维度

| 维度 | 定义 | 度量 | 失效表现 |
|---|---|---|---|
| **可变更性** | 一个需求能在 1–2 人日内、改 1–2 个模块完成 | 跨模块变更数 / 需求；任务周期 | 改一个字段动 5 个模块 |
| **可诊断性** | 出问题能在 1 小时内定位到 Run / 样本 / 依赖 | MTTR；trace 覆盖率 | 只能人肉翻日志 |
| **可传承性** | 新人或新 Agent 两天内能提交第一个 PR | Onboarding 时间；文档新鲜度 | 只有一个人知道怎么跑 |

三者必须同时建设。只拆模块不做可观测，会变成“改得快、查得慢”；只堆监控不做边界，会变成“看得见、改不动”。

---

## 3. 八个失控点

| # | 风险 | 早期信号 | 机制 | 负责 |
|---|---|---|---|---|
| 1 | 评测不可复现 | 同 Manifest 重跑分数不同 | Manifest + 不可变版本 + 重放门禁 | agent-eval |
| 2 | 外部 Provider 漂移 | 无代码变更但分数变了 | 适配器 + 版本锁定 + 契约测试 + 基线重冻结 | agent-eval |
| 3 | 数据库演进失控 | 迁移失败、回滚失败、上线卡住 | expand-contract + N-1 兼容 + 恢复演练 | agent-core |
| 4 | 契约漂移 | IDE/Agent 调用失败；前端类型不同步 | 契约文件 + 生成类型 + 快照测试 + 弃用周期 | agent-qa |
| 5 | 跨模块变更扩散 | 一个需求改 5 个模块 | `public.py` + import-linter + 任务拆分 | agent-core |
| 6 | 成本/噪声邻居 | 单租户跑满队列；账单突增 | 配额 + 预算熔断 + 公平调度 + kill switch | agent-eval |
| 7 | 测试腐化 | Flaky 变多；CI 从 5 分钟变 40 分钟 | 测试金字塔 + 隔离 flaky + 性能预算 | agent-qa |
| 8 | 文档腐化 | 文档与代码不一致；重复提问 | 文档即代码 + 链接检查 + 任务卡驱动 | 全体 |

## 4. 八个机制

### 4.1 契约优先与版本策略

三类契约，三种策略：

| 契约 | 载体 | 版本策略 | 破坏性变更 |
|---|---|---|---|
| 模块间 | `public.py` | 只增不改；DTO 加字段可选 | ADR + 调用方同步升级 |
| HTTP API | OpenAPI 3.1 | `/v1` 内向后兼容；N-1 支持 | 新 major，旧版保留 2 个 minor |
| MCP | `contracts/tools.yaml` | 只增工具；语义不变 | 新工具或新 major；提前 1 个 minor 公告 |

规则：

- 前端类型、MCP Schema、测试夹具必须从契约生成，禁止手写镜像。
- 契约变更必须触发契约测试；测试红则禁止合并。
- 新增字段必须有默认值；删除字段必须先标记 deprecated。
- 每个弃用项必须有：公告版本、移除版本、迁移指引。

### 4.2 数据库 expand-contract

MySQL DDL 不可回滚，规则比 PostgreSQL 更严：

```text
加字段：加 nullable → 双写 → 回填 → 切读 → 收紧
删字段：停写 → 观察 → 再删
改类型：新增列 → 双写 → 回填 → 切读 → 删旧列
```

硬规则：

- 一个迁移一个 DDL。
- 应用必须兼容 N-1 schema（滚动发布期间两边都能跑）。
- 迁移必须 `up → down → up` 验证。
- 不可逆迁移必须附数据快照方案。
- 大表变更使用 `ALGORITHM=INPLACE, LOCK=NONE` 或 gh-ost。
- 每季度一次真实恢复演练；未演练的备份视为不可用。

### 4.3 可复现门禁

评测平台的生命线，必须做成 CI 硬门禁：

- 同一 Manifest 重放 5 次，规则指标 100% 一致。
- Judge 指标分数差 ≤ 0.05，且差异可解释。
- 数据集版本不可变；`content_hash` 稳定。
- 模型、Prompt、Rubric、Judge 版本全部 pinning。
- 任何“分数变了”的 PR，必须指出是哪个版本变了。
- Judge 与人工一致率 κ ≥ 0.7 才允许进门禁。

### 4.4 适配器 seam

明确哪些地方**一定会变**，提前做成可替换：

| Seam | 当前实现 | 可能替换 | 契约 |
|---|---|---|---|
| 模型 | LiteLLM | 自建网关 / 新 Provider | `ModelGateway` |
| 存储 | 云 OSS | MinIO / S3 / 其他云 | `Storage` |
| 向量 | Qdrant | Milvus / pgvector | `VectorIndex` |
| 队列 | Redis + Celery | RabbitMQ / Temporal | `TaskRunner` |
| 认证 | API Key | OAuth 2.1 / 企业 IdP | `AuthProvider` |
| 传输 | HTTP MCP | stdio / 新协议 | `ToolRegistry` |

每个 seam 必须有：Protocol + 契约测试 + fake 实现。**换实现只改适配器，不改业务。**

### 4.5 适应度函数

把可维护性写成自动化测试：

| 属性 | 检查 | 失败后果 |
|---|---|---|
| 模块边界 | `import-linter` + 自定义 AST | CI 阻断 |
| 契约一致 | OpenAPI / `tools.yaml` / `public.py` 快照 | CI 阻断 |
| 可复现 | Manifest 重放 | CI 阻断 |
| 迁移可回滚 | up/down/up | CI 阻断 |
| 租户隔离 | 跨租户测试套件 | CI 阻断 |
| 性能 | benchmark 基线 | 超阈值告警/阻断 |
| 成本 | 单 Run 预算测试 | 超预算阻断 |
| 安全 | 依赖 CVE 扫描 | 高危阻断 |
| 文档 | 链接检查 + 任务卡字段完整性 | CI 阻断 |
| 边界与异常路径 | P0/P1 场景自动化（`edge-cases.md`） | CI 阻断 |

对应任务：`QUAL-01` ~ `QUAL-05`（见 `docs/planning/tasks/05-quality.md`）。

### 4.6 可观测性

没有可观测性，就没有可维护性。

- 每条日志、每个 span、每个指标都带 `trace_id`；评测链路带 `run_id`、`item_id`。
- 四张核心看板：队列深度、Run 成功率、单条 P95、Token 成本。
- 每个失败样本可下钻到：输入、输出、评分理由、Judge 调用、耗时、成本。
- 告警必须能定位到「租户 + Run + Provider」，而不是只报“错误率高”。
- 日志禁止包含完整 Prompt、样本正文、密钥。

### 4.7 发布护栏

- 新功能默认关闭，按租户/用户灰度。
- 三个 kill switch 必须有：Judge 关闭、语义检索关闭、MCP 关闭。
- 发布默认渐进式：内部 → 10% → 全量。
- 回滚脚本预写；回滚演练每季度一次。
- 数据库变更与应用发布解耦（expand-contract）。

### 4.8 技术债预算

技术债不是“以后再说”，而是有主人、有利息、有到期时间的账：

| 字段 | 说明 |
|---|---|
| 债务 | 什么问题 |
| 影响 | 拖慢什么、风险多大 |
| 利息 | 不还的话每月多花多少时间/钱 |
| 触发条件 | 什么情况下必须还 |
| 主人 | 谁负责 |
| 到期 | 什么时候必须处理 |

每季度留 **15–20% 容量**还债：依赖升级、Flaky 修复、迁移清理、文档补齐。没有预算的债，永远不会还。

## 5. 迭代节奏

| 项 | 建议 | 原因 |
|---|---|---|
| 任务粒度 | ≤ 2 人日 | 超过就拆，否则 review 和回滚都困难 |
| 分支寿命 | ≤ 2 天 | 长分支必冲突 |
| CI（快） | < 10 分钟 | 超过就没人愿意跑 |
| CI（全量） | < 30 分钟 | 夜间/合并前跑 |
| 发布频率 | ≥ 每周 | 发布越少，单次风险越大 |
| 兼容窗口 | API N-1；DB N-1 | 滚动发布必须两边都能跑 |
| 弃用周期 | 提前 1 个 minor 公告，保留 2 个 minor | 给客户端和 Agent 迁移时间 |

**小步快跑的前提是“每步可回滚”**，不是“跑得快”。

## 6. 评测平台特有维护点

| 点 | 做法 |
|---|---|
| Judge 漂移 | 每季度人工标注重新校准；κ < 0.7 不许进门禁 |
| 模型静默升级 | 所有模型版本 pinning；Provider 升级走「基线重冻结」流程 |
| 数据集污染 | 训练/评测集隔离；公开 benchmark 泄漏检测；动态数据集 |
| 基线冻结 | 基线不可变；换基线要写 ADR 并重跑历史对比 |
| 结果可比性 | 只有同 Suite、同数据集版本、同指标配置的 Run 才允许对比 |
| 成本失控 | 单 Run 预算、租户配额、Judge 缓存、采样 |
| 人工复核 | 保留小规模复核队列；Judge 不能完全替代人 |
| 删除与不可变冲突 | 不可变版本 vs 隐私删除：用脱敏墓碑（tombstone）或加密粉碎，禁止原地改历史 |

最后一条必须在设计期想好：**“不可变”和“可删除”是冲突的。**

## 7. Agent 协作下的可维护性

任务卡 + 子 Agent 会放大两个问题：重复抽象、表面完成。

对策：

- **任务卡就是规格**：输入/输出/验收/测试缺一不可。
- **架构测试是护栏**：不靠 Agent 自觉，靠 CI 拦截。
- **公共能力只允许 `core` 提供**：分页、错误、时钟、HTTP 客户端、租户上下文。
- **新增抽象必须走 ADR**：禁止“我先写一个，后面再统一”。
- **Review 重点放在边界和失败路径**，而不是代码风格。
- **交付必须附证据**：命令 + 输出 + 覆盖的边界。
- **每个模块有 owner，但 review 要轮换**，避免知识孤岛。

> Agent 没有记忆，文档和测试就是它的记忆。

## 8. 指标与健康度

| 指标 | 目标 | 数据来源 | 复盘频率 |
|---|---|---|---|
| 变更失败率 | < 15% | 发布记录 | 每月 |
| MTTR | < 1 小时 | 告警/事故记录 | 每月 |
| Lead time | < 3 天 | 任务系统 | 每月 |
| 部署频率 | ≥ 每周 | 发布记录 | 每月 |
| 快 CI 时长 | < 10 分钟 | CI | 每周 |
| Flaky 率 | < 1% | CI | 每周 |
| 重放成功率 | 100% | QUAL-02 | 每周 |
| Judge-人工一致率 | κ ≥ 0.7 | QUAL-02 | 每季度 |
| 跨模块变更/需求 | ≤ 2 模块 | PR 记录 | 每月 |
| 迁移回滚失败 | 0 | QUAL-03 | 每季度 |
| 新增 Connector | ≤ 1 人日 | 任务记录 | 每季度 |
| 新增 Evaluator | ≤ 1 人日 | 任务记录 | 每季度 |
| 新人首个 PR | ≤ 2 天 | Onboarding 记录 | 每季度 |
| 模块文档新鲜度 | 30 天内更新 | git 记录 | 每月 |

先盯四个：**变更失败率、MTTR、重放成功率、Flaky 率**。

## 9. 30 / 60 / 90 天

| 阶段 | 做什么 | 验收 |
|---|---|---|
| 0–30 天 | CI 门禁（lint/type/unit/contract/architecture/migration）；迁移规范；结构化日志 + trace_id；runbook 骨架 | PR 无法绕过门禁 |
| 31–60 天 | Manifest 重放门禁；Golden Set；Feature Flag/Kill Switch；技术债账本；依赖自动升级；第一次恢复演练 | 重放 100%；演练报告 |
| 61–90 天 | SLO/错误预算；事故复盘闭环；成本预算与看板；模块耦合度评审；弃用政策；第二次恢复演练 | SLO 看板；复盘行动项闭环 |

## 10. 红线

1. 评测结果不绑定 Manifest
2. 线上直接改 Judge Prompt / Rubric，不升版本
3. 数据集版本原地更新
4. 跨模块直接 JOIN 或 import 内部实现
5. 迁移不可回滚且无快照
6. 测试依赖真实 LLM / 真实 OSS
7. 日志里出现完整 Prompt、样本、密钥
8. MCP/API 工具契约无版本、无弃用周期
9. 单机 MinIO 作为生产唯一存储
10. 用覆盖率代替行为验证
11. 过早拆微服务
12. 模块没有 owner
